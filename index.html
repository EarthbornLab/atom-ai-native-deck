自进化长什么样：一次真实的推演

用户：「帮我看看这个会话里 LLM 的 token 消耗，我感觉最近特别费。」

01查现有工具面——没有现成的 token 统计视图
02查进程里有什么——发现有个服务每次 LLM 请求都广播一条用量事件，带 token 数
03查清字段（时间戳 / 请求 id / token 数）→ 写插件 v1：订阅事件、收集、按时间轴画成面板
04跑起来——字段猜错，面板显示 NaN
05读报错 → 追加 v2 修正 → 再跑，实时面板亮起

自进化的证据不是「它会写插件」，是 04 → 05 那个拐弯：它会根据报错给自己发新版本

动态的装卸机制：每个动作都带撤回

进程内每个动作都实现一对 effect（做）+ disposer（撤回）。规矩只有一条：每实现一个动作，必须同时写它的撤回动作。

effect · 装载时执行
① 创建文件，写入内容
② 订阅用量事件
③ 启动 token 面板服务
disposer · 卸载时逆序执行
③ 停掉面板服务
② 取消订阅
① 删掉这个文件

卸载完，进程回到干净状态——这是「万物皆插件」能装能卸的前提，也是原子化操作可组装的前提

但有件事 DSH 没做：插件跟着进程一起死

这不是缺陷——DSH 是 runtime 级别的框架，插件天然是进程形态的生命周期：进程结束，插件消失，无法形成共有记忆。持久化不归 runtime 管。这件事，谁来做？

Soloco 几个月前就意识到——并且已经开始做了

我们的答案：不止动作的持久化，还有动作组合的持久化，以及组成的 worker 和部门的持久化。

Soloco 已经接入 DSH，但是做的不同

Soloco 已经接入 DSH 作为 runtime 执行底座，同时接入它的插件生态——生态里每多一个插件，我们的组织就多一种能力。

沉淀之后：共享智力

原子化操作 固定格式 可组织拼接分享

这就是我们和 DSH 不一样的地方——共享智力，在 toB 场景有非常大的作用

从动作到部门：一条组装链

通过动作的版本迭代 + 沉淀，一系列动作变为一种能力；再通过能力的排列组合形成员工，通过员工的排列组合形成部门。

graph engineering：同一张图长上去

同一个组装动作逐层复利——每一层都可沉淀，沉淀了就能分享、能进化。这就是从个人能力到组织的 graph engineering。

动作是节点，组装是边——loop engineering 管一个循环怎么转，graph engineering 管能力怎么长成组织，这是硅谷当下在争的下一层抽象

组织资产的三级跳：生成 → 沉淀 → 进化 → 分享

①生成 → 沉淀怎么让产出留下来固定格式 + 完整生命周期——插件按统一格式落盘，effect / disposer 把它的装载、运行、卸载完整记录下来；进程死了，能力还在
②沉淀 → 进化怎么让留下来的变强版本迭代 + 组装升级——沉淀物带版本（v1 报 NaN → v2 修正），原子动作还能组装成能力、worker、部门，每一层都在原有资产上长
③进化 → 分享怎么让一个人的变成所有人的发布到 server + 推荐检索——沉淀的能力发布上 server；用户 B 有同样需求时先检索本地，miss 了由推荐算法从共享库命中，直接装上用

AI Native 组织把一次次对话中的判断与能力，沉淀为可复用、可组合、可共享的资产，形成组织级的「判断力」与「行动力」——人沉淀判断力，AI 沉淀行动力。组织能力第一次可以版本管理。

五层文档结构，逐层往下压

AGENTS.md宪法
只聊基本思想。第一句讲产品是什么、理念、愿景，然后列出下两层的 path。细节写进宪法，宪法就没人读了。
architecture技术架构
代码 high level 架构：agent 分几个角色、每个角色的作用；模块怎么划、职责边界在哪。跨功能的稳定契约。
prd产品设计
一个功能一个 prd，一个 prd 包含多个 design。付费模块是 prd：几种收费模式、什么情况触发。管边界，不管实现。
design实现方案
agent 实现代码的最小维度文档。写详细的 how，但不写代码细节——字段名 / CLI / schema 归代码。
coding唯一真相
design 的直接下游。代码细节由程序员和持有 design 的 agent 沟通决定。文档和代码打架，信代码。

prd + design 由产品经理角色书写，工程团队实现 · 冲突时按层级压：宪法 > architecture > prd > design

把我的 review taste 蒸馏出来

前提：你得先跟 agent 聊够多——每次纠正、否方案、拍决定都留在记录里，这就是语料。

┌本地 transcript~/.claude/projects + ~/.codex/sessions我和 AI 的全部聊天记录原文，本来就存在我电脑上，没有任何加工
│extract + rank五类信号关键词打分排序捞出我下判断的时刻：纠正(3)·概念(3)·引用(2)·拍板(2)·指令(1)——「帮我改个 typo」0 分，「不应该建抽象，职责归 daemon，就这么定」8 分
│distillagent 提名，我逐条拍板它问「你是否有条原则：写新代码前先找现有实现？例证是你这句原话」，我 accept / edit / reject——它只能提名，收不收永远是我拍板
│OWNER-TASTE.md交付物，进 git 仓库每条原则必须挂我的原话 + 出处（哪个会话、哪天）——语料里没有的不许编
└validate拿历史决策当考卷让它只看 TASTE 文件重判我过去真实处理过的 PR，和我当年的决定对答案——0 误报我才签字，没签字的版本不许拿去 review 任何人

root-cause-over-symptom[hard · must-fix]总纲：fix PR 第一问，治标还是治本
「治标不可耻，把治标伪装成治本才拦截。」

双 loop 闭环：机器提意见，机器修

taste 持续提意见，pr loop 持续修复，两边都是机器在转。人只做一件事：处理机器吵不出结果的分歧。

一人可以多 session 干活

这是前面所有结构化投入的兑现时刻——人处理事情的带宽被极大拓展：

→文档分层让每个 session 自带完整上下文——不需要我逐个交代背景
→taste loop 替我盯每个 session 产出的质量——不需要我逐个 review
→pr loop 替我把每个 PR 驱动到收敛——不需要我逐个跟进
→几个在实现、几个在 review、一个盯 PR、一个跑隔夜 goal——人从写代码的变成调度的
